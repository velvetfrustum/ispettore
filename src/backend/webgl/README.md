# WebGL backend

One capture backend for WebGL 1 and WebGL 2 contexts. Code is shared; a WebGL2-only feature is used only after checking that the context has it (the method, or the enum on the context object), so a WebGL1 context is never handed a WebGL2-only enum. `capture/contextInfo.js` records the detected `version` (1 or 2) in every capture package.

## Capture

- `intercept/apiSpec.js` defines intercepted methods declaratively, including which arguments reference other WebGL objects (`argResourceIndexes`) and which category of object a method creates (`resultKind`). The list is the WebGL2 surface; methods a WebGL1 context lacks are simply not wrapped.
- `intercept/extensions.js` defines extension methods (queried per extension with `extensionMethodsFor`) and wraps them on the objects returned by `getExtension`, so calls flow into the same journal as context commands. It covers the WebGL1 extensions that carry core WebGL2 features — `ANGLE_instanced_arrays`, `OES_vertex_array_object`, `WEBGL_draw_buffers`, `EXT_disjoint_timer_query` — plus `WEBGL_multi_draw`, `WEBGL_multisampled_render_to_texture`, `WEBGL_debug_shaders` and `EXT_disjoint_timer_query_webgl2`. Extension methods can create and delete tracked objects (e.g. `createVertexArrayOES`). Wrapping is idempotent per object.
- `intercept/contextWrappers.js` generates context wrappers from that specification.
- `capture/snapshotArguments.js` copies mutable call inputs before the native command executes and returns `{ values, types }`. `types` tags every argument (`number`, `string`, `null`, `undefined`, `sequence`, `array-buffer`, `shared-array-buffer`, `data-view`, `typed-array:<Constructor>`, `resource`, `readback-destination`), which keeps overloads that differ only by arity or argument type distinguishable after serialization. Typed arrays, `DataView`s, and views over a `SharedArrayBuffer` are copied over exactly their viewed byte range, so later mutation of the application's buffer cannot change a recorded command. Detached buffers and non-primitive sequence elements are rejected rather than recorded as empty or aliased data.
- `capture/contextInfo.js` captures the WebGL version, creation attributes, the limits the context exposes, supported extensions, and drawing-buffer/canvas dimensions, and observes effective canvas `width`/`height` changes. Each resize records the next command index plus canvas and drawing-buffer dimensions; `contextInfo.resizeTracking` reports unsupported or partial tracking. Metadata is captured before the context methods are wrapped, so it never pollutes the command journal.
- `capture/objectRegistry.js` assigns stable, per-context ids to created WebGL objects and retires them on deletion. Ids are never reused.
- `capture/commandJournal.js` connects the wrappers to the object registry, producing an ordered command list of `{ op, argTypes, args, resultId, failed, error }` where resource arguments are resolved to `{ ref: id }`. Commands whose arguments cannot be captured or resolved are still recorded, marked `failed` with a reason, and reported through `journal.failures`. GPU timings use core queries with `EXT_disjoint_timer_query_webgl2` on WebGL2, and the `EXT_disjoint_timer_query` object on WebGL1.
- `capture/livePreview.js` bakes each significant command's preview from the live context. WebGL2 reads through `READ_FRAMEBUFFER` and resolves multisampled or non-RGBA8 targets with a blit into an RGBA8 scratch texture; WebGL1 reads the single `FRAMEBUFFER` binding directly (it has no multisampled framebuffers or blits). The app's framebuffer and texture bindings are always restored.
- `capture/eventDetails.js` records Spector.js-style details for each significant command: named arguments (parameter names from `intercept/parameterNames.js`, adapted from Spector.js), stack trace, Spector's context state groups, the bound framebuffer, and for draws the program, shaders, attributes (with sampled vertex values), uniforms (with bound-texture parameters), uniform blocks and transform feedback. It classifies each state-setting command of the frame as valid, redundant, disabled or unused, against a baseline read at frame start. Values are stringified here (enum names from the context's own constants, bit masks), so the panel stays API-agnostic. WebGL2-only and extension-only queries run only when available; buffer contents (WebGL2 `getBufferSubData`) are read in batches — before the next buffer-modifying command or at frame end — because every read waits for the GPU. Program sources are stored once per capture in the package's `programs` map.
- `capture/canonicalize.js` reads DOM image sources into RGBA8 bytes and bakes the flip/premultiply unpack state.
- `serialize/serializeJournal.js` turns a journal into a versioned `ispettore-webgl-capture` package.
- `semantic/drawSemantics.js` maps draws to the Three.js object, material, program, textures, and composer pass that produced them.

DOM pixel sources and unknown extension objects that cannot be captured are recorded `failed` with the reason instead of being dropped or stringified. GPU-to-CPU commands are categorized as `readback` because their destination data is produced after the pre-call argument snapshot.

## Overview helpers

- `framebufferSnapshot.js` — FBO readback fallbacks (`readFramebufferViaBlit`, `readFramebufferViaCopyShader`) used by the Overview texture-preview path
- `parseTexImage.js` — decode `texImage2D`/`texSubImage2D` uploads for the texture inspector
- `spies/programSpy.js` — program/shader tracking for the texture and program inspectors

Do not import this folder from `ui/`, `adapters/`, or `shared/capture/` — only from `backend/bootstrap` / `injected.js`. Keep WebGPU in its independent backend (`../webgpu/`).
